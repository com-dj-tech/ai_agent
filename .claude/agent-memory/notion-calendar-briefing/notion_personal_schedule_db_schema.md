Notion "개인일정 DB" (database_id: `1a2bddfb-604b-4edf-82ec-b30107d2bd8a`)의 실제 프로퍼티는 다음과 같다 (2026-07-10 확인):

| 표시 프로퍼티 | 타입 | 비고 |
|---|---|---|
| 제목 | title | |
| 유형 | select | 예: "미팅". 스펙 문서의 "일정유형"이 아니라 "유형"이 실제 키. |
| 날짜 | date | 단일 date 객체 (start/end), "날짜/시간"이 아니라 "날짜"가 실제 키. 종료시각은 보통 비어있음(null). |
| 장소 | rich_text | |
| 메모 | rich_text | 안건 + 참석자 명단이 자유 텍스트로 함께 들어있음. 별도의 "참석자" 프로퍼티는 존재하지 않음. |
| 상태 | select | 옵션: `예정` / `완료` / `취소` 뿐. **"캘린더 등록 완료" 옵션은 존재하지 않음.** |
| 중요도 | select | 예: "중간" |

**존재하지 않는 프로퍼티**: 참석자(별도 필드), 반복 여부. → 참석자/반복 정보는 메모 텍스트에서 파싱해야 함.

**Why:** 원래 지시 스펙(개인일정 DB 조회 6필드 + 상태값 "캘린더 등록 완료")을 그대로 가정하고 작업하면 존재하지 않는 프로퍼티/옵션을 조회·업데이트하려다 실패한다.

**How to apply:**
- 이 DB를 조회할 때는 제목/유형/날짜/장소/메모/상태/중요도 7개 프로퍼티만 신뢰할 것.
- "캘린더 등록 완료" 여부를 반영해야 할 때: 상태를 `예정`으로 설정(또는 이미 완료된 일정이면 `완료`)하고, Google Calendar 이벤트 링크는 메모 필드에 텍스트로 append하는 방식으로 대체한다 (전용 URL/역링크 프로퍼티 없음).
- 참석자 이메일이 없으면 메모에 이미 명단이 텍스트로 있으므로 그대로 활용하거나 Calendar 이벤트 description에 옮겨적으면 된다.
